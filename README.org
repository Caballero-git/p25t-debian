#+TITLE: Debian on the Teclast P25T tablet, from a microSD card
#+STARTUP: overview

* What this is
Scripts and kernel patches to build a microSD card that runs Debian 13
on a Teclast P25T tablet (model P9A6, Rockchip RK3566), with mainline
Linux 7.3.

The tablet's Android is never touched: the card boots instead of it, and
without the card the tablet starts Android as before. Everything on the
card is built from this repository and from sources downloaded at fixed
versions; nothing downloaded is stored here.

*Status (2026-10-26):* a working card can be made from this repository
alone, following "Building a card" from a blank card and an empty work
folder (done on 2026-10-22 on a Linux Mint 22 PC; the card boots, sway,
Wi-Fi, Bluetooth and sound work). A running card can take a new kernel or
start-up system ("Updating a running card"). Work continues: an
on-screen keyboard for use without any keyboard, a user guide.

* Tested on the tablet
With a card made from this repository (2026-10-22..24):
| What                              | Result                                                  |
|-----------------------------------+---------------------------------------------------------|
| boot, login, sudo                 | works                                                   |
| Wi-Fi                             | works                                                   |
| Bluetooth keyboard                | works (pair, trust, connect once)                       |
| keyboard on USB-C (host)          | works                                                   |

| speakers, headphones, volume keys | works                                                   |

* What you need
- The tablet: Teclast P25T, model P9A6 (Rockchip RK3566).
- A microSD card of 8 GB or more (A1 recommended). It will be erased.
- A USB card reader.
- A PC (called =pc_linux= here): x86-64, a Debian-family Linux (Debian,
  Ubuntu, Linux Mint), =sudo= rights, internet access, and free disk
  space: about 3.6 GB for steps 1-3 (2 GB kernel source, 1 GB kernel
  build, 0.5 GB boot loader) and 6 GB free for step 4 (Debian).
- Packages (one line):
  #+begin_example
  sudo apt install git build-essential gcc-aarch64-linux-gnu bc bison flex libssl-dev libelf-dev kmod cpio patch swig python3-dev python3-setuptools libgnutls28-dev uuid-dev curl bzip2 mmdebstrap qemu-user-static binfmt-support debian-archive-keyring gpg gdisk dosfstools parted rsync
  #+end_example

* Building a card
Choose a work folder, written =<WORK>= below (for example =~/P25T=).
Everything goes into it: this repository as =<WORK>/p25t-debian=, the
kernel source as =<WORK>/linux=, and what the scripts build in
=<WORK>/p25t-debian/build/= (never committed). Run the scripts as your
normal user; any script that needs root asks for =sudo= itself. Each
script explains itself in its header.

0. Get this repository:
   #+begin_example
   cd <WORK>
   git clone https://github.com/Caballero-git/p25t-debian.git
   #+end_example
1. Kernel source: Linux 7.3 with the P25T patches.
   #+begin_example
   bash <WORK>/p25t-debian/tools/get_kernel.sh
   #+end_example
   It downloads the 7.3 release from kernel.org (a shallow git clone of
   the tag =v7.3=: about 300 MB, 2 GB on disk) into =<WORK>/linux=,
   creates the branch =p25t= and applies the 30 patches of
   =kernel/patches/= (see its README). It ends with
   =OK: ... branch p25t = Linux v7.3 + 30 P25T patches=.

2. Kernel build: the kernel, the Wi-Fi driver, and both collected for
   the card.
   #+begin_example
   bash <WORK>/p25t-debian/tools/build_kernel.sh
   bash <WORK>/p25t-debian/tools/build_wifi.sh
   bash <WORK>/p25t-debian/tools/pack_kernel.sh
   #+end_example
   - =build_kernel.sh= configures the kernel (=kernel/p25t-base.config=
     plus =kernel/p25t.fragment=) and compiles it out of the source tree,
     into =build/kernel/=. It takes long: half an hour on a PC with two
     cores, more on a slow laptop; if it stops, run it again and it
     continues. It ends with
     =OK: kernel 7.3.0-p25t built=.
   - =build_wifi.sh= builds the tablet's Wi-Fi driver (AIC8800, not part
     of mainline Linux) from github.com/radxa-pkg/aic8800 at a fixed
     commit, checked against the source of the driver that runs on the
     tablet. About a minute. Run it again after every =build_kernel.sh=.
   - =pack_kernel.sh= collects the kernel, its four device trees, the
     modules and the Wi-Fi firmware, with checksums, into
     =build/kernel-pack/= for the card.

3. Boot loader and start-up system (about a minute each, plus the
   downloads the first time):
   #+begin_example
   bash <WORK>/p25t-debian/tools/build_uboot.sh
   bash <WORK>/p25t-debian/tools/build_initramfs.sh
   #+end_example
   - =build_uboot.sh= builds mainline U-Boot (tag =v2026.10-rc5=) and
     puts it with Rockchip's BL31 (=rk3568_bl31_v1.46.elf=, checked by
     its sha256, never stored here) into =build/u-boot/uboot.itb=: the
     file the tablet's own first-stage loader reads from the card. The
     tablet's loader in its internal memory is never changed.
   - =build_initramfs.sh= builds the start-up system ("stage 1"): a static
     busybox and =initramfs/init=, in =build/stage1/initramfs.cpio.gz=.
     At every boot it writes a log onto the card and hands over to
     Debian; holding a volume key at power-on keeps it in stage 1 instead,
     a rescue system with a shell on the USB-C port.
   - Both builds are reproducible: with the same compiler (the author
     uses Ubuntu 24.04's) every PC gets the same files, and each script
     says whether its result is identical to the author's. Another
     compiler version gives other checksums, which is no error.

4. Debian (10-25 minutes after the questions):
   #+begin_example
   bash <WORK>/p25t-debian/tools/build_debian.sh sway
   #+end_example
   (or =console= instead of =sway= for a text-only card; without a name
   it lists the desktops it finds in =debian/=). It asks for =sudo=, then
   its questions, as the Debian installer does:
   - user name and password on the tablet, and the host name (=p25t=);
   - the Wi-Fi network and its password (optional; empty = none);
   - an SSH public key for logins from the PC (optional);
   - time zone, language and keyboard: it prints the PC's values and
     asks whether to use them, or asks for each;
   - whether to add the optional programs of =tested.txt= (see "Programs"
     below).
   It shows a summary and builds only after a "y". Debian 13 (trixie)
   arm64 comes from =deb.debian.org=, without Recommends, into
   =build/rootfs-<DESKTOP>/=, with the kernel modules and Wi-Fi firmware
   of step 2 and the tablet settings of =debian/common/setup.sh= and
   =debian/<DESKTOP>/setup.sh=. The passwords are stored only on the new
   system (as hashes), never in a file of the build. To build again,
   remove the old folder first (the script says how).

5. The card's boot part. Put only the new card into the reader and find
   its name with =lsblk= (a whole disk such as =/dev/sdb= or
   =/dev/mmcblk0=, about the card's size; written =<DEVICE>= below).
   #+begin_example
   bash <WORK>/p25t-debian/tools/make_boot_part.sh image
   bash <WORK>/p25t-debian/tools/make_boot_part.sh write <DEVICE>
   #+end_example
   =image= makes the boot part as a file (partition table, U-Boot three
   times, an empty partition =P25TBOOT=); =write= asks for =sudo=, shows
   the card and ERASES it after you type =YES=, writes the boot part and
   reads it back to compare. It refuses the PC's own disks, anything that
   is not a removable, USB or SD disk of 4-255 GB, and a card that already
   carries a P25T system; to reuse such a card add =--erase-p25t-card=
   (it asks a second time).
6. Debian, kernel and start-up system onto the card (a few minutes):
   #+begin_example
   bash <WORK>/p25t-debian/tools/install_card.sh sway
   #+end_example
   (the same desktop name as in step 4). It finds the card by its
   =P25TBOOT= partition (only one P25T card may be in the PC), asks for
   =YES=, makes the root partition from 1 GiB to the end, copies Debian
   and checks every file, and puts the kernel, its four device trees and
   the initramfs on =P25TBOOT= with a checksum list (=CARD-SHA256SUMS=).
   It ends with =OK: the card is ready=. If the PC's file manager opens
   the card's partitions, eject them there before taking the card out.
7. Plug a keyboard into the tablet's USB-C port (a USB-C keyboard, or a
   USB keyboard through an adapter or hub), put the card into the tablet
   (switched off) and power it on. After about 20 s the login prompt
   appears on the screen; on a sway card, sway starts after the login.
   The internal Android is untouched: without the card the tablet starts
   it as before.
   - The card starts with USB-C as a host (for the keyboard). It does
     not charge in that mode. =set-dtb device= switches to USB-C as
     a device from the next boot on: charging, and a serial console and
     network for a PC over the cable; =set-dtb host= switches back.
   - Logins: the user and password of step 4 on the screen, or over SSH
     as =<USER>@<HOST>.local= when the tablet is on Wi-Fi (with USB-C as
     a device also at =192.168.7.2= over the cable).
   - A Bluetooth keyboard: pair it once with =bluetoothctl= (=scan on=,
     =pair <ADDRESS>=, =trust <ADDRESS>=, =connect <ADDRESS>=).
   - Every boot writes a log onto the card (=P25TBOOT/logs/=, readable on
     the PC).

* Programs
Each folder of =debian/= has four lists, one package per line followed
by what it is (e.g. =zathura  # PDF viewer=):
| List             | Installed?                     | What                               |
|------------------+--------------------------------+------------------------------------|
| =packages.txt=   | always                         | needed, and proven on the tablet   |
| =tested.txt=     | if you answer "y"              | optional, proven on the tablet     |
| =under_test.txt= | no; =sudo apt install= by hand | being tried                        |
| =discarded.txt=  | no                             | tried and dropped, with the reason |
=debian/common/= goes on every card; =debian/sway/= or =debian/console/=
adds the desktop. A program moves from =under_test.txt= to =tested.txt=
(or =packages.txt=) once it works well, or to =discarded.txt= with the
reason. The cards install without Recommends: a program that needs one of
its Recommends gets it listed next to it (qutebrowser: =qt6-wayland=). On
a sway card the build also makes the installed optional programs the
defaults for =xdg-open= (PDF: zathura, web: qutebrowser, music and video:
mpv).

To add another desktop, copy =debian/sway/= to =debian/<NAME>/= and
change its lists, =setup.sh= (run inside the new system after
=debian/common/setup.sh=) and =config/= (the user's =~/.config=).

* On the tablet
Commands of the card (in =/usr/local/bin=):
| Command                               | What                                                          |
|---------------------------------------+---------------------------------------------------------------|
| =set-dtb= (also =set-role=)           | camera (=rear=, =front=) and USB-C role (=host=, =device=) for the next boot; alone it shows both |
| =cam-snap=, =rear-snap=, =front-snap= | take a PNG photo                                              |
What the card does by itself:
- Volume keys and headphone jack: the keys change the volume, the
  speakers are off while headphones are plugged in (=p25t-audio=, run by
  triggerhappy).
- At every boot the start-up system writes a log onto the card
  (=P25TBOOT/logs/=, readable on the PC).
- =sudo p25t-bootlog= adds a report of the running Debian there
  (=boot-N-debian.txt=: failed services, network, warnings, kernel log),
  for when the tablet shows nothing. While testing new features it can
  repeat by itself, 1 min after boot and then every 4 min:
  =sudo systemctl enable --now p25t-bootlog.timer= (=disable --now=
  stops it). It is off by default: a card in daily use should not write
  to its boot partition all day.
Other things to do on the tablet:
- A Wi-Fi network later (or another one): =<SSID>= is the network's name;
  it asks for the password.
  #+begin_example
  wpa_passphrase <SSID> | grep -v '#' | sudo tee -a /etc/wpa_supplicant/wpa_supplicant-wlan0.conf
  sudo systemctl restart wpa_supplicant@wlan0
  #+end_example
- The sway card starts sway after the login on the tablet's screen (tty1)
  after a 3 s countdown; a key during it, or a file =~/.no-sway=, keeps
  the text console. Other consoles (Ctrl+Alt+F2 ... F6) and SSH logins
  stay text.

* Updating a running card
The scripts in =tablet/= put a new kernel or a new start-up system on a
card in use, without making a new card. They were used at every step
while the kernel patches and device trees of this repository were
developed and tested, and they are needed again whenever a feature is
added or changed. Each one checks what it copies, keeps what it replaces
(on =P25TBOOT= and in =~/boot-backups/= on the tablet), keeps
=CARD-SHA256SUMS= up to date and can put the previous version back
(=restore=). Each explains itself in its header.
| Script                       | What                                                          |
|------------------------------+---------------------------------------------------------------|
| =tablet/install_modules.sh=  | the modules and the Wi-Fi firmware of a new kernel            |
| =tablet/deploy_kernel.sh=    | the new kernel and its four device trees (the =set-dtb= choice stays) |
| =tablet/deploy_initramfs.sh= | a new start-up system (stage 1)                               |
=<USER>@<HOST>.local= is the tablet on Wi-Fi (or =<USER>@192.168.7.2=
over the USB-C cable); =<TAG>= names the update in the backup files, for
example the date (=20261026=).
- A new kernel: build it as in steps 1-2 (after changing a patch or the
  configuration), copy the pack and the scripts to the tablet, then on
  the tablet install the modules and the kernel, and reboot:
  #+begin_example
  scp -r <WORK>/p25t-debian/build/kernel-pack <WORK>/p25t-debian/tablet <USER>@<HOST>.local:
  #+end_example
  #+begin_example
  sudo bash tablet/install_modules.sh <TAG> kernel-pack
  sudo bash tablet/deploy_kernel.sh <TAG> kernel-pack
  sudo reboot
  #+end_example
  If the new kernel does not start, the header of =deploy_kernel.sh= says
  how to go back (two files on =P25TBOOT= with the card in the PC, then
  =restore= on the tablet).
- A new start-up system: build it as in step 3, copy it with its
  checksum (the =*= takes both files) and the scripts, then on the
  tablet:
  #+begin_example
  scp -r <WORK>/p25t-debian/build/stage1/initramfs.cpio.gz* <WORK>/p25t-debian/tablet <USER>@<HOST>.local:
  #+end_example
  #+begin_example
  sudo bash tablet/deploy_initramfs.sh initramfs.cpio.gz
  sudo reboot
  #+end_example
  =sudo bash tablet/deploy_initramfs.sh restore= puts the previous one
  back.
